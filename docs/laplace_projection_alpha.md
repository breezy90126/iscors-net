# 拉普拉斯投影能不能像 DLS 一樣分出不同的 α？

**結論：不能——而且不是「工程沒做好」，是這個量測本身的結構決定的。**

在 per-pixel 層級，α 跟「速率分佈的寬度」是**同一個自由度**，不是兩件可以互相分開的事。
拉普拉斯反演只是把 `G(τ) = A/(1+γτ^α)` 的 (γ, α) 換一組座標寫出來，不會生出新資訊。
唯一還有意義的用法是 **ROI 平均後的 bulk 診斷**——但那必須先修掉第六節的 finite-T 偏差，
否則它會純粹因為偏差而給出假陽性。

所有數字都可以重跑（純標準庫，無相依）：
`python3 scripts/laplace_identifiability.py`（第一～五節）、
`python3 scripts/finite_t_bias.py`（第六～七節）。工具在 `utils/laplace_spectrum.py`。

---

## 一、先講最關鍵的：DLS 的 kernel 跟這裡不一樣

CONTIN 在 DLS 能work，前提是**單一 q**：

```
DLS:    g1(τ) = ∫ P(Γ) e^(−Γτ) dΓ ,  Γ = D q²      每個粒徑 = 一條純指數
```

每個粒徑對應一條乾淨的指數，反演才有「把兩群分開」的意義。

iSCAT/iSCORS 的 per-pixel ACF **不是這樣**。一個 pixel 收的是 PSF 涵蓋的**整段 q** 積分過的訊號——
這正是為什麼模型是 `A/(1+γτ^α)` 這種 FCS 型代數式，而不是指數和。而且：

> **α = 1 的 `1/(1+γτ)`，恰好就是 `p(Γ) = (1/γ)e^(−Γ/γ)` 的拉普拉斯轉換。**

也就是說，**單一、完全均勻的成分，在拉普拉斯空間裡本來就長成一條橫跨所有 decade 的寬分佈**。
它的 log₁₀ 寬度是解析值 `π/(√6·ln10) = 0.557 decade`（`utils/laplace_spectrum.py` 的 self-test 會跑出 0.54，符合）。

所以在 iSCAT 裡，「譜很寬」**不等於**「多分散」——寬度主要是成像光學的 q 積分造成的。
拿 DLS 的指數 kernel 去反演 q 積分過的資料，本身就是 kernel mismatch：
你反出來的東西是「粒徑分佈」和「光學 q 權重」糾纏在一起，原則上分不開。

## 二、α 就是譜寬（EXP 3）

對每個 α 反演出正的速率譜，看它長什麼樣：

| α | 反演殘差 | 譜寬 (decade) | 峰數 |
|---|---|---|---|
| 0.6 | 0.0020 | 0.88 | 1 |
| 0.8 | 0.0006 | 0.70 | 1 |
| 1.0 | 0.0003 | 0.54 | 1 |
| 1.2 | 0.0010 | 0.43 | 1 |
| 1.5 | 0.0033 | 0.31 | 1 |

**全部單峰**，寬度隨 α 單調變化。fitter 容許的整段 α ∈ (0,2) 都能用一個正的速率譜表示，
殘差遠低於雜訊 → 拉普拉斯反演對 α **完全沒有鑑別力**，它只是把 α 換算成寬度。

「分出不同的 α」在這裡是個 category error：反演給你的是 Γ 的分佈，
而 α ↔ 分佈寬度是一對一的。沒有「兩群、各自有自己的 α」這種可解的東西。

## 三、兩個方向的簡併都成立（EXP 4、EXP 5）

**正向**：真的有兩群（速率比 R），用單一 (γ, α) 去 fit——

| R | 單成分殘差 | per-pixel 測得到？ | 最佳單成分 fit |
|---|---|---|---|
| 2 | 0.00054 | 否 | γ=0.157, **α=0.98** |
| 3 | 0.00137 | 否 | γ=0.167, **α=0.94** |
| 5 | 0.00297 | 否 | γ=0.187, **α=0.88** |
| 10 | 0.00605 | 否 | γ=0.226, **α=0.79** |
| 30 | 0.01212 | 否 | γ=0.313, **α=0.62** |
| 100 | 0.01772 | 否 | γ=0.435, **α=0.45** |

即使速率差 **100 倍**，殘差 0.018 還是低於 per-pixel 雜訊 0.041 → 測不到。
而且看最後一欄：**混合不會消失，它變成一個較低的 α**。α 本來就已經在扛多分散度了。

**反向**：α=0.6 的異常擴散曲線，用兩條 α=1 指數去 fit
→ 殘差 0.0100 ≪ 雜訊 0.041 → **INDISTINGUISHABLE**。

兩個方向都簡併，代表這不是選錯方法，是資訊本身不夠。

## 四、資訊上限：kernel 條件數 + 實測雜訊

**Laplace kernel 的奇異值**（τ = 1..128，2.11 decade）：

```
1.00  0.289  0.108  0.0437  0.0188  0.0075  0.0030  0.0012  0.00037  0.00005
```

**實測 per-pixel 雜訊**（T=2500 半段、BIN_FACTOR=2 的 4 px，模擬量測而非假設）：
RMS = **0.041**，且尾端 τ 特別糟：τ=1 是 1.1%，τ=128 是 **42%**。

→ 高於雜訊的奇異方向只有 **4 個**。而且「4 個成分」指的是 4 個平滑奇異方向
（振幅、質心、寬度、一點偏度），**不是 4 群可分辨的族群**。剩下的都是 regulariser 在講話，不是資料。

**順帶一個獨立的問題**：EXP 2 同時測到大 τ 有系統性負偏差（τ=128 低估 **33%**，
finite-T 扣平均造成的）。這件事跟拉普拉斯無關，但它的影響比一句話大得多，
所以獨立寫在第六節。

## 五、兩個 lever：加長 τ 沒用，只有平均有用

**Lever A — 加長 τ 視窗（EXP 6）**：

| τ grid | 4.1% 雜訊 | 0.41% | 0.14% |
|---|---|---|---|
| 1..128 (10 lags, 2.11 dec) | 4 | 6 | 7 |
| 1..512 (12 lags, 2.71 dec) | 4 | 7 | 9 |
| 1..2048 (13 lags, 3.31 dec) | 4 | 8 | 10 |

**在真實的 per-pixel 雜訊下，τ 拉長 16 倍一個成分都沒多。** 綁住的是雜訊，不是 τ 視窗。

**Lever B — 平均 N 個 pixel（EXP 4b）**：能偵測到的最小速率比

| N px | 雜訊 | 可偵測的 R |
|---|---|---|
| 1 | 4.13% | 無 |
| 16 | 1.03% | R ≥ 30 |
| 100 | 0.41% | R ≥ 10 |
| 400 | 0.21% | R ≥ 5 |
| 900 | 0.14% | R ≥ 3 |
| 3600 | 0.07% | R ≥ 3 |

平均是唯一有效的 lever——但平均掉的正是**空間資訊**。也就是說
**沒有 per-pixel 的 α 分離地圖，只有 ROI 級別的答案**。

而且這張表只算了**統計雜訊**。第六節會說明，一旦平均到這個程度，
真正的限制已經不是雜訊而是**系統偏差**。

## 六、finite-T 偏差為什麼重要（`scripts/finite_t_bias.py`）

用**樣本平均**（而不是真平均）去算 ACF，會系統性壓低相關性。壓低量大致是一個
**跨 τ 的固定負偏移**，所以 G(τ) 值越小的地方、比例上被打得越重：
τ=1 只差 +0.3%，τ=128 差 **−33%**。

### 6.1 它不是均勻的——這才是問題所在

如果偏差對每個 pixel 都一樣，那它只是一個常數平移，
slope-3 的截距 `b = mean(Y−3X)`、z-scoring、GEVD 全都會自動吸收掉，無害。
但實測（T=2500，α_true=0.8）**它取決於該 pixel 自己的 γ**：

| γ_true | γ̂ (固定 α) | α̂ (自由 α) | CV²̂/CV² | ΔX | ΔY |
|---|---|---|---|---|---|
| 0.03（慢） | 0.0398 (**+33%**) | 0.914 | 0.906 | −0.123 | −0.043 |
| 0.12 | 0.1349 (+12%) | 0.858 | 0.980 | −0.051 | −0.009 |
| 0.50 | 0.4786 (−4%) | 0.864 | 0.997 | +0.019 | −0.002 |
| 1.00（快） | 0.8511 (**−15%**) | 0.879 | 0.999 | +0.070 | −0.001 |

三個後果：

1. **γ 對比被壓縮到真值的 87%**（1.523 → 1.330 decade）。慢的被推快、快的被推慢。
2. **α̂ 被系統性灌水**（真值 0.8 → 量到 0.86–0.91）。由第二節，α 就是譜寬，
   所以這等於**系統性低估了異常程度／多分散度**。
3. **`global_alpha=True` 讓情況更糟**。α 固定時，偏差沒地方去，全部灌進 γ
   （慢 pixel +33%）；α 自由時偏差大多被 α 吸收、γ 反而還好。但 per-pixel α
   本來就不可辨識（第二節），所以這是個真實的兩難，不是可以隨手改掉的設定。

### 6.2 為什麼 half-split 抓不到它

這是最關鍵的一點。**cross-half 驗證抓的是 variance，不是 bias。**
兩個半段有相同的 T、相同的底層動力學，所以**拿到完全相同的偏差**。
一個由 finite-T 造成的假結構會：

- 在兩半之間完美重現 → 通過 Section 2 的 reliability 檢定；
- 在 GEVD 裡表現為高 λ 的「可複現軸」；
- 長得像一個乾淨的生物訊號。

也就是說，**這個 repo 整套驗證框架對這類誤差是盲的**。
「可複現」不等於「是真的」——只等於「不是隨機雜訊」。

### 6.3 對 slope=3 這條結論的影響：不痛，而且方向是安全的

偏差同時動 X 和 Y，所以會污染量到的斜率。實測的換算是

```
s_measured ≈ (s_true − 0.028) / 0.873
```

| s_true | s_measured |
|---|---|
| 0.4 | 0.426 |
| 0.5 | 0.541 |
| 3.0 | 3.403 |

量到的斜率被**灌水約 8%**。所以你量到 within-cell ~0.5，真值大概是 **~0.47**——
離 3 更遠。**這個偏差不威脅「within-cell 斜率不是 3」的結論，反而讓它更強。**

### 6.4 怎麼修

由便宜到貴：

1. **限制 τ_max**：τ≤16 偏差 ≤5%（代價：dynamic range 從 2.11 掉到 1.2 decade）。
2. **模型加一個自由基線** `G = A/(1+γτ^α) − c`：c 直接吸收那個固定負偏移。
   代價是多一個 DOF，而且在 10 點曲線上跟 α 有相當程度的簡併。
3. **解析修正**：偏差 ≈ `(1/T)·Σ_k C(k) ≈ 2τ_int·C(0)/T`。fit → 由模型算 τ_int
   → 修正 → 重 fit，迭代兩次就收斂。這是正解。
4. **用全長記錄**（T=5000）而不是半段：偏差直接減半。
   注意現在 Section 2/3 是**用半段算權重、套到全段的圖**，兩者偏差不同。

## 七、bulk 速率譜測試的意義（以及為什麼必須先修 6）

### 7.1 它問的是一個 (γ, CV²) 直方圖問不到的問題

retrospective 記錄的是「LLPS 要看 bulk 雙峰，結果 bulk 單峰」。
但那個檢定是在 **(γ, CV²) 的 per-pixel 直方圖**上做的，它問的是：

> **「有沒有兩種 pixel？」** ← 這是**空間**問題

只有當兩相在**像素尺度上分開**時才看得到。而 per-pixel 的 γ 是那個 pixel 內部
所有成分的**混合平均**——如果兩相在次像素尺度共存（凝聚體小於繞射極限、
或稀相根本瀰漫在整個核裡、或同一分子有結合/自由兩態），
那**每個 pixel 都看到同一個混合**，直方圖**必然單峰**。單峰在這種情況下不是證據。

速率譜問的是完全不同的問題：

> **「單一條 ACF 裡面有沒有兩個衰減速率？」** ← 這是**動力學**問題

它偵測的是**像素內部的共存**，正是 per-pixel 直方圖結構上看不到的東西。
對核內凝聚體（除了核仁大多在繞射極限附近或以下）來說，這個區別是實質的。

### 7.2 它還能裁決 α 的物理意義

現在 fit 出來的 global α < 1。這有兩種完全不同的解釋：

- **(i)** 真的是異常次擴散（壅擠、黏彈性）；
- **(ii)** 只是多群正常擴散的混合——由第三節，混合**就是**表現為較低的 α。

per-pixel 這兩者無法區分（EXP 5）。但 bulk 平均 ~10³ px 後統計雜訊掉到 0.13%，
R ≳ 3 就能分辨。**這是這份資料在不換採集的前提下，還能問出的最有價值的問題。**

### 7.3 但是：bulk 是 systematics-limited，不是 noise-limited

這是把第六節和這一節綁在一起的關鍵，也是我一開始講得太輕的地方。

| | 絕對量級 (G 單位) |
|---|---|
| **finite-T 系統偏差（RMS）** | **0.0257** |
| 統計雜訊 @ 1 px | 0.0413 |
| 統計雜訊 @ 1000 px | 0.0013 |
| 統計雜訊 @ 3000 px | 0.0008 |
| R=3 混合的特徵 (f=0.5) | 0.00137 |
| R=10 混合的特徵 | 0.00605 |
| R=100 混合的特徵 | 0.01772 |

平均 pixel 會把統計雜訊除以 √N，**但偏差一點都不會掉**。
到 1000 px 時偏差已經是雜訊的 **20 倍**，而且**比所有要找的混合特徵都大**。

實測：把單成分模型 fit 到**有偏差的**曲線，殘差 0.0068 = 1000 px 的 3σ 門檻的 **5.5 倍**
——也就是說，**不修偏差就跑 bulk 測試，它會純粹因為偏差而回報「需要不只一個成分」**。

方向也很糟：偏差壓低慢速尾端 → 看起來慢成分更少 → **遮蓋**真的慢族群（false negative）；
而修過頭 → **製造**一個假的慢峰（false positive）。偏差的形狀正好就是要找的訊號的形狀。

### 7.4 所以這個測試值得做，但有嚴格的前置條件

- **先做 6.4 的修正**，否則結論無意義。
- 修完後，1000 px 的敏感度（僅統計）：

  | 少數相佔比 f | R=3 | R=10 | R=30 | R=100 |
  |---|---|---|---|---|
  | 0.50 | ✓ | ✓ | ✓ | ✓ |
  | 0.20 | ✓ | ✓ | ✓ | ✓ |
  | 0.10 | ✗ | ✓ | ✓ | ✓ |
  | 0.05 | ✗ | ✓ | ✓ | ✓ |
  | 0.02 | ✗ | ✗ | ✓ | ✓ |

  → **陰性結果能排除的是「f ≳ 0.2 且 R ≳ 3」或「f ≳ 0.05 且 R ≳ 10」的雙相**，
  排除不了少量的慢族群。有這個數字，陰性結果才有意義，而不是空話。
- **絕對譜寬不可解讀**（第一節的 q 積分）；只有**峰數**、以及
  **不同 ROI 之間的相對比較**（例如核仁 vs 核質）是有意義的。

## 八、跟這個 repo 已有結果的一致性

三件事互相印證：

1. **deliverable 已經用 `global_alpha=True`**（cell 4）——整個核共用一個 α 純量。
   這個工程選擇跟上面的分析一致：per-pixel α 本來就不可辨識。
2. **`fit_gamma_alpha_batched(n_components=2)` 已經存在**（含 Occam penalty）——
   那就是一個 2 點的拉普拉斯反演。它沒被用在 deliverable 裡；EXP 4 說明了為什麼 per-pixel 用不了。
3. **最強的一條**：Section 3 已經把**整條 G(τ) 當 feature 做 full-τ GEVD**，
   用 half-split 驗證，結論是穩健生物軸只有 ~1 條。任何拉普拉斯反演都是**同一組 G(τ) 的確定性函數**，
   由 data processing inequality，它的可複現資訊量**不可能超過**已經量到的上限。
   → 拉普拉斯投影**不會生出新的可複現軸**，最多把那 ~1 條軸換成比較好解釋的單位。

## 九、那什麼做法真的能分開不同的 α？

**要 q 解析度，不是拉普拉斯反演。**

MSD ~ t^α 時，中間散射函數是

```
f(q,t) = exp(−c q² t^α)     →     衰減時間 τ_c(q) ∝ q^(−2/α)
```

**α 是從 τ_c 對 q 的冪次讀出來的**，不是從單一 q 的曲線形狀讀出來的。
兩群即使在某個 q 有相同 τ_c，只要 α 不同，在 q 掃描下就會分開——
這是跟「單一 q 的曲線形狀」正交的一個資訊軸，也正是 per-pixel ACF 缺的那個維度。

實作路徑就是對影像做空間傅立葉 → **DDM / STICS**，得到 `ISF(q, τ)`，
然後每個 q 各自 fit（要反演的話也是每個 q 各自反演，這時 kernel 才是對的）。
STICS 那條線在 `legacy/deep-learning-stics` 分支上有既有程式碼可以接。

這跟 retrospective 的落點一致：要真正的新軸，只能**換採集**或**加正交量測**。

## 十、實務建議

按這個順序做：

1. **先修 finite-T 偏差**（6.4）。這是唯一有 blocking 性質的一步：
   它同時影響現有的 γ 圖（對比壓縮 13%、α 灌水）**和**任何 bulk 慢速端結論，
   而且 **half-split 抓不到它**（6.2）。建議走 6.4 的第 3 項（解析迭代修正），
   最低限度也要做第 4 項（改用全長記錄）。

2. **不要做 per-pixel 拉普拉斯地圖。** 每個 pixel 的譜寬只是 α 的重新編碼，
   多峰結構是 regulariser 產生的，不會通過 half-split。

3. **修完之後**跑 bulk / ROI CONTIN：

   ```python
   from utils.laplace_spectrum import roi_spectrum
   res = roi_spectrum(CACHE['G'], CACHE['nuc'], RECON_TAUS,
                      G1=CACHE['G1'], G2=CACHE['G2'])
   print(res['n_px'], res['n_peaks'], res['verdict'])
   ```

   函式會用 half-split 算雜訊、跟單成分 fit 比較、檢查峰數在兩半是否重現，
   並在殘差落在 finite-T 偏差可解釋的範圍時提出警告。
   值得做的比較是**核仁 ROI vs 核質 ROI**（用 `Y < percentile(Y,12)` 那個核仁遮罩）——
   相對比較比絕對譜寬可靠得多（第一節的 q 積分）。

4. **想要真的分 α → 走 DDM/STICS 的 q 解析路線**（第九節）。這是唯一能給出
   **新的獨立資訊軸**的做法；前三項都只是把既有的 ~1 條軸弄乾淨。
